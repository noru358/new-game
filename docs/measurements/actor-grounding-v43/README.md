# v43 배우·지형 접점 확인

기준은 로컬 v42 통합 커밋 `f21f2b63e600c0a27233bbef87d4cc96bb9643dc`다. 공식 Godot 4.6.89cea1439, Apple M3, OpenGL 4.1 Compatibility의 화면 밖 격리 창에서 실제 3D 메시와 Sprite3D를 렌더했다. 보통 사용자 저장 경로에는 접근하지 않았다.

## 원인과 수정

- 석계단 상단 `(3780,1180)`의 뿔짐승은 지형 메시를 꺼도 849개 중 71개 실루엣 픽셀만 보였다. 불투명 수목 `(4060,1390)`이 몸을 가렸다. 수목 중심을 `(4250,1390)`으로 옮겼고 동일한 기록에서 나무 몸통·잎과 2D 충돌이 함께 이동한다. 나무, 투명도, 크기, 수량은 유지했다.
- 실제 계단 표면은 보행 높이보다 2~3.5 맵 단위 위에 그려졌으며 바위길·평평한 장식 바닥에도 작은 높이 차이가 있다. 일반 적의 그림자와 이동·피격 좌표는 원래 지면에 두고 몸체만 0.04 세계 단위 들어 올렸다. 실루엣 하단의 가림을 없애기 위한 표현 조정이다. 플레이어·보스, 충돌·AI·저장·보상·보스 시계는 건드리지 않는다.
- 석조 아트 helper가 장착된 최종 후보에서는 관문 마디의 최대 장식 높이가 2 맵 단위다. 아트 변경의 정적 drawcall과 삼각형 비용은 `../jungle-worn-stone/README.md`에 별도로 기록했다.

대표 전후 PNG: [기준](before-stair-high-960.png), [후보 960](after-stair-high-960.png), [후보 1280](after-stair-high-1280.png). 원시 수치: `before-report-960.json`, `after-report-960.json`, `after-report-1280.json`. 픽셀 차이는 같은 장면에서 적 Sprite3D만 켜고 끄며 세며, 수목·지형 가림을 분리하려고 지형 메시도 켜고 껐다. 안티앨리어싱/조명에 따른 몇 픽셀의 흔들림은 있을 수 있다.

`tests/verify_actor_terrain_depth.gd`는 계단 하·중·상·마루, 바위길, 관문 상단, 사원 테라스·징검돌, 수로 시험 다리의 9개 표본을 검사한다. 최종 Mac 960·1280에서 각각 9/9 통과했다. 변경된 수목의 실제 충돌 위치도 확인한다. 기존 적 표현324개, 정글 경로73개, 지형·수로·사원 관련 회귀도 통과했다. 이는 고정 표본의 지형·시야 검사이며 자연 한 판, 사람의 가독성/미감 수용, 장시간 성능 결과가 아니다.

최종 합본의 기존 [72개 검사 결과](full-suite-results.tsv)는 모두 exit0이다. 손상된 설정 파일을 고의로 넣는 `verify_play_settings`의 엔진 파서 오류는 v42에서도 같은 입력에서 발생했고 검사 결과는211/0이다. [보스 시계401개](boss-countdown-native.log), [출정 UI268개](ui-flow-native.log), [석조 이동960](worn-960-native.log)·[1280](worn-1280-native.log)이 실제 Mac에서 통과했다. [정글 강변 긴 경로](route-960-report.json)는 약4,956 맵 단위 정상속도 입력으로 목적지에 도달했지만 [캡처 종료 로그](route-960-native.log)에 자원1개 정리 경고가 반복된다. 본격 게임창의 장시간 자원 거동은 확인하지 않았다.
